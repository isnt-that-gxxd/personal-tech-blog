## 개요

LLM(대규모 언어 모델)은 사용자가 입력한 문장을 사람처럼 그대로 읽고 이해하는 것이 아니다.

컴퓨터가 문장을 계산할 수 있도록 텍스트를 작은 단위로 나누고 숫자로 변환한 뒤, 각 요소 사이의 관계를 계산하는 과정이 필요하다.

이 과정을 이해하기 위해 <strong>Token(토큰), Embedding(임베딩), Attention(어텐션), Transformer(트랜스포머)</strong>를 알아볼 필요가 있다.

## Token이란?

사용자가 다음과 같은 문장을 입력했다고 가정한다.

> 나는 오늘 회사에서 디자인 작업을 했다.

AI가 이 문장을 그대로 읽는 것은 아니다.

먼저 문장을 <strong>Token(토큰)</strong>이라는 작은 단위로 나눈다.

토큰은 흔히 단어라고 생각하기 쉽지만 **단어와 정확히 같은 개념은 아니다.**

영어의 `unbelievable`처럼 하나의 단어가 여러 토큰으로 나뉠 수도 있고, 한국어 역시 하나의 단어나 어절이 여러 토큰으로 분리될 수 있다.

따라서 토큰은 다음과 같이 이해할 수 있다.

> **Token = AI가 텍스트를 처리하기 위해 사용하는 기본적인 텍스트 단위**

## 왜 문장을 Token으로 나눌까?

컴퓨터는 사람이 문장을 읽는 것처럼 텍스트의 의미를 그대로 처리하지 않는다.

따라서 텍스트를 계산할 수 있는 형태로 변환해야 한다.

전체 과정을 단순화하면 다음과 같다.

```text
문장 입력
    ↓
Token으로 분리
    ↓
각 Token을 계산 가능한 형태로 변환
    ↓
AI 모델에서 처리
```

여기서 Token을 계산할 수 있는 숫자 표현으로 만드는 과정과 관련된 개념이 <strong>Embedding(임베딩)</strong>이다.

## Embedding이란?

Embedding은 단어나 Token의 특징과 관계를 컴퓨터가 계산할 수 있도록 **숫자들의 묶음으로 표현하는 방법**이다.

예를 들어 강아지라는 개념이 있다고 가정한다.

설명을 위해 매우 단순화하면 다음과 같은 숫자 형태로 표현할 수 있다.

```text
강아지

[0.81, 0.32, -0.14, 0.72, ...]
```

고양이 역시 다른 숫자들의 묶음으로 표현될 수 있다.

```text
고양이

[0.79, 0.29, -0.10, 0.68, ...]
```

위 숫자는 실제 모델의 값을 나타내는 것이 아니라 개념을 설명하기 위한 예시다.

또한 각각의 숫자에 사람이 직접 다음과 같이 의미를 지정하는 것도 아니다.

```text
0.81 = 동물
0.32 = 귀여움
0.14 = 크기
```

모델이 학습하는 과정에서 여러 특징과 관계가 복잡한 숫자 표현 안에 형성된다.

## 숫자로 표현하면 무엇이 달라질까?

텍스트를 숫자로 표현하면 컴퓨터가 **개념 사이의 관계를 수학적으로 계산**할 수 있다.

예를 들어 의미적으로 다음 두 관계를 비교해 보자.

```text
강아지 ↔ 고양이

강아지 ↔ 자동차
```

일반적으로 강아지와 고양이는 강아지와 자동차보다 의미적으로 관련성이 높다.

의미적 관계를 학습한 Embedding을 이용하면 이러한 관련성을 수학적으로 비교할 수 있다.

따라서 사용자가 다음과 같이 요청했을 때 관련 있는 개념을 처리할 수 있는 기반이 만들어진다.

> 강아지와 비슷한 동물을 알려줘.

다만 실제 LLM에서 사용하는 Token Embedding과 의미 검색에 사용하는 Embedding은 목적과 학습 방식이 다를 수 있다.

## 같은 단어라도 의미가 다를 수 있다

하지만 Embedding만으로 LLM의 문장 처리 방식을 모두 설명할 수 있는 것은 아니다.

다음 두 문장을 비교해 보자.

> 나는 **배**를 먹었다.

> 나는 **배**를 타고 제주도에 갔다.

두 문장에 등장하는 `배`라는 글자는 같지만 의미는 다르다.

두 번째 문장에는 `타고`, `제주도`, `갔다` 등의 내용이 함께 등장한다.

따라서 주변 Token과의 관계를 고려하면 여기서 `배`는 과일보다는 탈것과 관련된 의미라는 것을 처리할 수 있다.

이처럼 문장 안에 존재하는 요소들이 **서로 어떤 관계를 가지고 있는지 계산하는 데 중요한 개념이 Attention**이다.

## Attention이란?

Attention은 일반적으로 **주의 또는 집중**이라는 뜻을 가지고 있다.

LLM에서는 문장을 처리할 때 **각 Token이 다른 Token의 정보를 얼마나 참고할지 계산하는 방식**으로 이해할 수 있다.

예를 들어 다음 문장이 있다고 가정한다.

> 철수가 영희에게 사과를 주었다. 그녀는 그것을 먹었다.

`그녀`를 처리할 때는 앞에 등장한 `영희`와의 관계가 중요하다.

`그것`을 처리할 때는 `사과`와의 관계가 중요하다.

이를 단순화하면 다음과 같다.

```text
그녀 ───────── 영희

그것 ───────── 사과
```

여기서 AI가 사람처럼 다음과 같이 생각하는 것은 아니다.

> 그녀는 영희를 말하는구나.

각 Token 사이의 관계를 수학적으로 계산한 결과를 이용해 문맥을 처리한다.

위 예시는 Attention의 역할을 이해하기 위한 단순화된 설명이며, 실제 모델이 반드시 해당 관계를 정확하게 판단한다는 의미는 아니다.

## Self-Attention이란?

Transformer에서 중요한 개념 중 하나가 <strong>Self-Attention(셀프 어텐션)</strong>이다.

Self-Attention은 간단하게 말하면 다음과 같다.

> **하나의 입력 안에 존재하는 Token들이 서로의 관계를 계산하는 방식**

예를 들어 다음과 같은 문장이 있다.

> 강아지가 공을 물었다.

`강아지`, `공`, `물었다`를 각각 완전히 독립적으로 처리하는 것이 아니라 서로 어떤 관계가 있는지를 함께 계산한다.

이를 통해 어떤 대상이 행동했고 어떤 대상이 그 행동과 연결되어 있는지 등 문맥을 처리할 수 있는 기반이 만들어진다.

## Attention과 Transformer의 차이

Attention과 Transformer는 같은 개념이 아니다.

<strong>Transformer는 Attention을 핵심 요소로 활용하는 신경망 구조(Neural Network Architecture)</strong>다.

단순하게 비유하면 다음과 같다.

```text
Transformer = 공장 전체

Attention = 공장에서 사용하는 핵심 장치 중 하나
```

Transformer 구조는 2017년 발표된 **Attention Is All You Need** 논문에서 제안됐다.

현재의 LLM들이 사용하는 구조가 당시 논문의 Transformer와 완전히 동일한 것은 아니지만, 현대 LLM 발전에 중요한 기반이 된 연구다.

## GPT의 T는 Transformer를 의미한다

GPT는 **Generative Pre-trained Transformer**의 약자다.

각 단어의 의미는 다음과 같다.

| 단어 | 의미 |
| --- | --- |
| Generative | 새로운 내용을 생성하는 |
| Pre-trained | 대규모 데이터로 미리 학습된 |
| Transformer | Transformer 구조를 기반으로 하는 |

따라서 GPT를 단순하게 풀어보면 다음과 같다.

> **미리 학습된 Transformer 기반 생성 모델**

## 지금까지의 LLM 처리 과정

지금까지 배운 내용을 연결하면 다음과 같다.

```text
사용자가 문장 입력
    ↓
Tokenization
텍스트를 Token 단위로 분리
    ↓
Embedding
계산 가능한 숫자 표현으로 변환
    ↓
Transformer
    └─ Attention을 활용해 Token 사이의 관계 계산
    ↓
다음 Token 예측
    ↓
Token 생성
    ↓
과정 반복
    ↓
최종 답변 생성
```

실제 LLM 내부에서는 이보다 훨씬 많은 계산이 이루어진다.

또한 생성된 Token을 다시 입력 문맥에 포함해 다음 Token을 예측하는 과정을 반복한다.

따라서 위 구조는 LLM의 실제 구현을 그대로 나타낸 것이 아니라 **전체적인 작동 원리를 이해하기 위해 단순화한 구조**다.

## 실제 AI 서비스에서는 어떻게 활용될까?

지금까지 배운 개념은 AI의 내부 원리를 이해하는 데만 사용되는 것은 아니다.

Embedding은 실제 AI 서비스를 개발할 때도 활용할 수 있다.

예를 들어 디자인 업무 자료를 검색하는 AI 서비스를 만들었다고 가정한다.

사용자가 다음과 같이 검색한다.

> 다국어 UI 작업할 때 정리했던 자료 찾아줘.

하지만 실제 문서에는 `다국어 UI`라는 표현이 없고 다음과 같이 작성되어 있을 수 있다.

> 스페인어 번역 이후 버튼 텍스트가 길어져 레이아웃 수정

단순히 동일한 글자가 포함되어 있는지를 찾는 방식이라면 두 문서의 관계를 찾기 어렵다.

반면 의미적인 관계를 이용하는 검색에서는 서로 다른 표현이라도 관련 있는 내용을 찾는 데 활용할 수 있다.

이러한 방식은 이후 배우게 될 <strong>RAG(Retrieval-Augmented Generation, 검색 증강 생성)</strong>와 같은 AI 시스템에서도 중요하게 등장한다.

## LLM은 이전 대화를 어디까지 기억할까?

여기까지 이해하면 새로운 문제가 생긴다.

사용자가 AI와 매우 긴 대화를 했다고 가정한다.

```text
[긴 대화 내용]

...

사용자:
아까 내가 만들겠다고 한 게임이 뭐였지?
```

AI가 이전 내용을 참고하려면 한 번에 처리할 수 있는 정보의 범위가 필요하다.

여기서 <strong>Context Window(컨텍스트 윈도우)</strong>라는 개념이 등장한다.

Context Window는 간단하게 다음과 같이 이해할 수 있다.

> **모델이 한 번의 추론에서 처리할 수 있는 입력과 생성 내용의 범위**

이 개념은 AI를 이용한 개발에서도 중요하다.

프로젝트가 커지면서 코드와 파일이 많아지면 AI에게 프로젝트 전체를 무작정 전달할 수 없기 때문이다.

따라서 어떤 정보를 AI에게 제공할 것인지, AI가 프로젝트의 구조를 어떻게 파악하게 만들 것인지도 중요해진다.

Context Window가 길다고 해서 모든 이전 정보를 항상 정확하게 활용하는 것은 아니며, 실제로 어떤 정보를 참고할 수 있는지는 서비스의 대화 기록 관리 방식에도 영향을 받는다.

## 정리

이번 글에서 기억해야 할 핵심 개념은 다음과 같다.

| 용어 | 의미 |
| --- | --- |
| Token | AI가 텍스트를 처리하기 위해 사용하는 기본적인 텍스트 단위 |
| Embedding | 텍스트의 특징과 관계를 계산할 수 있도록 숫자로 표현하는 방법 |
| Attention | Token 사이의 관계를 계산해 문맥을 처리하는 데 사용되는 핵심 방식 |
| Self-Attention | 하나의 입력 안에서 Token들이 서로의 관계를 계산하는 방식 |
| Transformer | Attention을 핵심 요소로 사용하는 신경망 구조 |
| GPT | Generative Pre-trained Transformer |
| Context Window | 모델이 한 번의 추론에서 처리할 수 있는 정보의 범위 |

전체적인 흐름은 다음과 같이 정리할 수 있다.

```text
텍스트 입력
    ↓
Token으로 분리
    ↓
Embedding을 통해 숫자로 표현
    ↓
Transformer에서 문맥 처리
    └─ Attention을 이용해 Token 사이의 관계 계산
    ↓
다음 Token 예측
    ↓
결과 생성
```

다음 글에서는 **Context Window와 AI의 기억**을 중심으로 긴 대화나 대규모 코딩 프로젝트에서 AI가 왜 이전 정보를 놓치는지 알아볼 것이다.
